# Mall 项目功能开发交接文档

更新时间：2026-07-29

本文用于将当前商城项目交接给后续开发人员。内容以当前工作区代码为准，不以历史聊天记录或构建产物为准。项目根目录为 `E:\projects\mall`。

## 一、项目结构与启动方式

项目是 Maven 多模块 Spring Boot 3 项目，主要模块如下：

| 模块 | 职责 |
| --- | --- |
| `mall-common` | 通用返回体、异常、工具和公共枚举 |
| `mall-user` | 用户、地址、权限、站内消息、积分和会员 |
| `mall-marketing` | 商品、收藏、优惠券、评价、浏览历史 |
| `mall-order` | 购物车、订单、支付、退款、物流 |
| `mall-server` | 启动模块、控制器聚合、数据库 schema 和 Flyway |
| `mall-web` | 用户端 Vue 3 + TypeScript + Element Plus |
| `mall-admin` | 管理后台 Vue 3 + TypeScript + Element Plus |

后端构建命令：

```powershell
mvn.cmd -pl mall-server -am test -DskipTests
```

用户端构建命令：

```powershell
Set-Location mall-web
npm.cmd run build
```

管理后台构建命令：

```powershell
Set-Location mall-admin
npm.cmd run build
```

后端数据库配置在 `mall-server/src/main/resources/application.yml`。数据库迁移由 Flyway 管理，迁移文件位于 `mall-server/src/main/resources/db/migration`。

## 二、总目标：九类功能

原始目标是完成以下九类能力，并保持代码可读、复杂逻辑有中文注释、数据库变更同时归档到 schema 和 Flyway：

1. 售后体验完善
2. 站内消息中心
3. 用户成长体系：积分、会员等级、签到、积分兑换
4. 商品对比与收藏增强：降价提醒、到货提醒等
5. 营销活动：秒杀、拼团、满减、限时折扣
6. 后台数据分析
7. 后台用户管理
8. 安全能力
9. 性能与稳定性

当前并非九项全部完成，下面明确列出完成边界和剩余工作。

### 3.2 优惠券释放和统一审计日志

优惠券全过程必须记录在现有 `operation_log`，禁止重新创建 `coupon_usage_log`。

相关文件：

- `mall-marketing/src/main/java/com/mall/entity/CouponAuditLog.java`

当前优惠券事件类型：

| event_type | 含义 |
| --- | --- |
| `RECEIVED` | 用户领取 |
| `LOCKED` | 下单锁定 |
| `RELEASED` | 取消订单/支付失败释放 |
| `REFUNDED` | 全额退款后释放 |

退款逻辑在 `mall-order/src/main/java/com/mall/service/impl/RefundServiceImpl.java`。只有累计退款金额达到订单实付金额后才释放优惠券，部分退款不能提前释放。`releaseCoupon` 通过状态条件保证重复回调幂等。

审计日志表定义位于 `mall-server/src/main/resources/db/schema.sql` 的 `operation_log`。字段只允许保留一份：`event_type`、`user_coupon_id`、`user_id`、`coupon_id`、`order_id`、`remark`。历史 diff 中曾出现重复归档，当前 schema 已整理为唯一字段。

迁移文件：`mall-server/src/main/resources/db/migration/V5__coupon_audit_fields.sql`。该迁移使用 `information_schema` 判断字段和索引是否存在，适用于旧库升级和新库初始化。

状态机：
```
仅退款: PENDING(0) → APPROVED(1) → REFUNDING(2) → REFUNDED(3)
退货:   PENDING(0) → APPROVED(1) → RETURN_SHIPPING(5) → REFUNDED(3)
换货:   PENDING(0) → APPROVED(1) → EXCHANGE_SHIPPING(6) → REFUNDED(3)
拒绝:    PENDING(0) → REJECTED(4)
```

4. `GET /api/points/redemptions` 前端 API 和兑换记录 UI 尚未完成。

## 六、数据库变更规范

任何新增表或字段都必须按以下顺序：

1. 先修改 `mall-server/src/main/resources/db/schema.sql`，保证全量初始化库可用。
2. 再新增递增版本的 Flyway 文件，例如 `V9__xxx.sql`。
3. Flyway 文件必须考虑已有数据库重复执行问题，优先使用 `IF NOT EXISTS` 或 `information_schema` 检查。
4. 不得创建已经被用户否定的 `coupon_usage_log`。
5. 修改 `operation_log` 前先确认字段是否已存在，避免重复归档。
6. 迁移完成后检查 `mall-server/target/classes` 只是构建产物，不是源代码依据。

## 七、代码质量与已知问题

1. 部分历史文件存在 UTF-8 被错误解码后的中文乱码。新增代码必须使用正常 UTF-8 中文；不要为了修乱码而一次性重写无关文件。
2. 部分 Vue 文件曾被压缩成单行，尤其是 `mall-web/src/views/user/PointsCenter.vue`、`UserCenter.vue` 及后台若干列表页面。后续修改应逐步展开模板、脚本和样式，复杂逻辑添加中文注释。
3. 不要直接修改 `dist` 或 `target` 作为源代码修复。它们由构建生成。
4. `CouponAuditLog` 只是映射 `operation_log` 的业务别名，不是新表；任何人看到该类都不要再创建审计表。
5. 需要补充服务层并发测试和空数据测试，特别是无评价商品、无库存兑换、重复签到、重复退款回调。
